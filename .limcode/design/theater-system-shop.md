# 小剧场：系统商店 设计方案

## 1. 定位

这是一张单行小剧场表，一行就是当前宿主的整套系统面板。助手说的“行”在表里落成 6 列：任务、状态、系统背包、商店、点数、称号。

| 列 | 谁写 | 说明 |
|---|---|---|
| 任务 | AI | 当前只挂 1 个任务，带难度和奖励点数 |
| 状态 | AI（前端可写“已放弃”） | 进行中 / 已完成 / 已失败 / 已放弃 |
| 系统背包 | 只由前端写 | AI 不碰，原样保留 |
| 商店 | AI 生成，前端标记售空 | 默认 6 件，按称号决定品级概率 |
| 点数 | AI 加，前端扣 | AI 只在任务完成时加，购买时由前端扣 |
| 称号 | AI | 品级色 + 称号名 + 累计完成数 |

DDL 全部用普通 TEXT，不写 NOT NULL、CHECK、UNIQUE，避免填表校验失败。格式约束只放在提示词里当“软约定”，前端解析时宽松兼容，解析不出来就直接显示原文。

## 2. 称号阶梯

称号由“累计完成任务数”决定，AI 每次完成任务时 +1 并检查是否升阶。

| 品级色 | 称号 | 累计完成 |
|---|---|---|
| 绿 | 系统菜鸡 | 0–2 |
| 蓝 | 见习宿主 | 3–7 |
| 紫 | 精英宿主 | 8–14 |
| 橙 | 传说执行官 | 15–24 |
| 红 | 至尊宿主 | 25–39 |
| 黑 | 万界任务巨星 | 40+ |

前端以累计完成数为准计算品级，AI 写错颜色时也能显示正确。

## 3. 点数经济

任务奖励按难度：

| 难度 | 奖励 |
|---|---|
| 简单 | 5–15 点 |
| 普通 | 20–40 点 |
| 困难 | 50–90 点 |
| 噩梦 | 100–200 点 |

物品价格按品级：绿 5–20、蓝 20–50、紫 50–120、橙 120–250、红 250–500、黑 500–1000。大致是一个普通任务买得起一件蓝色物品。

商店品级出现比例（AI 大致遵循即可）：

| 当前称号 | 绿 | 蓝 | 紫 | 橙 | 红 | 黑 |
|---|---|---|---|---|---|---|
| 绿 | 60% | 30% | 10% | - | - | - |
| 蓝 | 40% | 35% | 20% | 5% | - | - |
| 紫 | 20% | 35% | 30% | 12% | 3% | - |
| 橙 | - | 25% | 35% | 28% | 10% | 2% |
| 红 | - | - | 25% | 35% | 30% | 10% |
| 黑 | - | - | 10% | 30% | 35% | 25% |

另加一条：每次刷新至少有 1 件物品是当前点数买得起的，避免商店一直看得到买不到。

## 4. 回合流程

AI 每次填表按这个顺序：

1. 读「状态」。
   - 已完成 / 已失败 / 已放弃：发布新任务，状态改回“进行中”。不加点，不改称号。
   - 进行中：根据正文判断。完成 → 状态改“已完成”，点数 + 奖励，称号累计 +1 并检查升阶；失败 → 状态改“已失败”，其他不动；没结果 → 全部不动。
2. 读「商店」。只要有任何物品带【已售空】，整个商店按当前称号重新生成 6 件；没有售空就原样保留。
3. 「系统背包」永远原样保留，不增删、不改写。
4. 「点数」只在第 1 步判定完成的那一次增加，其他情况一律不动，绝不扣减。

防重复加点的关键：加点只发生在“进行中 → 已完成”的那一次更新。下回合读到“已完成”只负责换新任务。

商店刷新我选的是“有售空就整店刷新”。规则简单，AI 不容易出错；代价是没买的物品也会被换掉。如果助手更想要“只替换售空的那几件”，改提示词第 2 步即可，前端不受影响。

## 5. 前端交互

- 购买：未售空且点数 ≥ 价格时可点。确认后同一次写入三格：点数 − 价格、背包追加该物品、该物品前加【已售空】。点数不足时按钮置灰并提示差多少。
- 放弃任务（可选）：任务进行中时可点，确认后把状态写成“已放弃”，下回合 AI 换新任务。
- 展示：称号徽章按品级色渲染（黑阶用黑金渐变）；任务卡显示类型、难度、奖励；商店为 2 列卡片网格，按品级描边；背包为横向标签列表。

## 6. 单元格软格式

前端解析规则都是宽松的，下面是提示词里给 AI 的写法建议：

- 任务：`【类型·难度】任务名：任务描述（奖励N点）`。前端取最后一个“数字+点”作为奖励。类型有剧情、搞怪、整活、色色、挑战等。
- 状态：直接写四个词之一。前端按关键词识别。
- 系统背包：`物品名（品级）`，多件用英文分号 `;` 分隔。空背包写“空”。
- 商店：每件 `品级｜物品名｜N点｜来源世界·效果说明`，多件用英文分号 `;` 分隔。也兼容半角 `|`、换行分隔。售空由前端在该件最前面加【已售空】。
- 点数：只写一个整数。前端取第一个整数。
- 称号：`品级·称号名（累计完成N）`，例如 `紫·精英宿主（累计完成9）`。

## 7. 表格提示词

### note

系统商店是宿主绑定的“万界任务系统”面板，固定只维护 1 行。系统会发布各种任务：推进剧情的正经任务、搞怪整活、羞耻挑战、色色任务、离谱恶搞都可以，必须贴合当前正文场景和人物，能在接下来的剧情里实际完成或失败。商店贩卖来自各个平行宇宙的物品：修仙丹药、西幻魔法道具、科幻装备、末世物资、都市黑科技、成人向道具等，每件有品级和点数价格。

字段写法：
- 任务：【类型·难度】任务名：任务描述（奖励N点）。难度为简单 5-15 点、普通 20-40 点、困难 50-90 点、噩梦 100-200 点。同时只有 1 个任务。
- 状态：只写 进行中 / 已完成 / 已失败 / 已放弃 之一。
- 系统背包：由前端维护，你必须原样保留，禁止增删或改写任何内容。
- 商店：6 件物品，每件写成 品级｜物品名｜N点｜来源世界·效果说明，用英文分号 ; 分隔。品级为 绿/蓝/紫/橙/红/黑。价格：绿 5-20、蓝 20-50、紫 50-120、橙 120-250、红 250-500、黑 500-1000。物品名要有梗，效果要具体好玩。
- 点数：只写一个整数。
- 称号：写成 品级·称号名（累计完成N）。累计完成 0-2 绿·系统菜鸡；3-7 蓝·见习宿主；8-14 紫·精英宿主；15-24 橙·传说执行官；25-39 红·至尊宿主；40 以上 黑·万界任务巨星。

商店品级比例按当前称号：绿称号以绿蓝为主、少量紫；蓝称号开始出现橙；紫称号偶尔出红；橙称号偶尔出黑、不再出绿；红称号以橙红为主；黑称号红黑大量出现。每次刷新至少 1 件物品当前点数买得起。

### updateNode

每回合按顺序处理：
1. 状态为 已完成、已失败 或 已放弃：发布 1 个新任务，状态改为 进行中。本步不加点数、不改称号。
2. 状态为 进行中：根据最新正文判断。任务达成 → 状态改为 已完成，点数加上该任务奖励，称号累计完成数 +1 并按阶梯检查升级；任务明确失败 → 状态改为 已失败，其余不动；尚无结果 → 全部不动。
3. 商店中只要有任何物品带【已售空】，按当前称号整体重新生成 6 件物品；没有售空则商店原样保留。
4. 系统背包永远原样保留。点数只在第 2 步任务达成时增加，其他任何情况不得修改，绝不扣减。

### initNode

初始化插入 1 行：任务按当前正文发布 1 个简单或普通任务，状态 进行中，系统背包 空，商店按绿称号生成 6 件，点数 0，称号 绿·系统菜鸡（累计完成0）。

### insertNode

只在表为空时插入 1 行，其余时候只更新这一行。

### deleteNode

不删除这一行。

### ddl

```sql
CREATE TABLE system_shop ( -- 系统商店
  row_id INTEGER PRIMARY KEY, -- 行号
  task TEXT, -- 任务
  task_status TEXT, -- 状态
  bag TEXT, -- 系统背包
  shop TEXT, -- 商店
  points TEXT, -- 点数
  title TEXT -- 称号
);
```

## 9. 风险与待确认

- 写回能力：现有 scene 契约只有删除（`deleteEntities`），没有“改单元格”。购买和放弃需要写三格，实现前要先确认表格层是否有单元格更新 API，没有就需要补一条受控写入通道。这一点我还没验证。
- 并发覆盖：用户在 AI 填表进行中购买，AI 的写入可能把扣过的点数或售空标记覆盖回去。建议填表进行中禁用购买按钮。
- AI 漏写：AI 可能误改背包或扣点。前端以“背包只追加”为准做不了强校验，只能靠提示词约束，必要时在更新后对比前后背包并提示。
- 概率只是软约束：AI 不会真随机，比例只能大致遵循。
