原功能 → 新位置（以 modules/qq-v2/ui/app.js 3735–3751、校验 5123–5148 为准）：
1. 二级页标题「上下文」、返回 → 公共骨架标题栏「‹ 设置」，点击跳转 qq-settings-root.html；右侧无按钮。
2. 数字字段「宿主上下文条数」（min=0）→ 卡片内步进器，默认 3，减到 0 为止。
3. 文本字段「标签提取」（placeholder「content」）→ 纵向块行单行输入框。
4. 文本字段「标签排除」（值用「、」拼接，placeholder「例如：status、table」）→ 纵向块行单行输入框。
5. 数字字段「聊天历史条数」（min=0）→ 步进器，默认 100。
6. 保存：失焦 / change 即保存，无保存按钮，成功无提示；错误显示在卡片下方红字状态行（role=alert）。
7. 校验与源码一致：保存任一字段时，标签提取和标签排除都会重新校验（源码这两项不受 field 限定），所以改条数时若标签排除有非法项，也会报「标签排除包含无效标签：…」。
8. 保存成功后标签排除输入框回填规范化值：去掉尖括号（<x> / </x> / <x/>）、忽略大小写去重、用「、」连接；分隔符与标签名规则照 domain/story-context-tags.js。
新增 / 改动的交互：
· 源码没有区块标题，原型新增分组标题「酒馆上下文」（1–3 项）与「QQ 聊天」（第 4 项）。
· 源码两条提示放在输入框 title（悬停才可见），原型改为字段下方可见的灰色说明，并用 aria-describedby 关联。
· 条数由数字输入框改为步进器：步进器只产生 ≥0 的整数，「上下文条数必须是 0 或更大的整数」在原型里正常操作不会出现，校验逻辑仍保留。
· 标签排除未改成 chip 展示，保持单行文本输入。
· 保存失败时界面保留用户输入的值，不回滚（原型行为，未核对源码失败后是否重绘）。
原型模拟：「模拟读取失败」整页只显示一行「读取设置失败」；「模拟保存失败」开启后每次保存都显示「保存失败」；「模拟切换聊天（下次保存）」让下一次保存显示「当前聊天已切换，未保存」后自动复位。
这只是视觉原型，数据为示例，不连接真实小手机。
